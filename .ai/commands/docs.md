# /docs

## Propósito

Crear o mejorar documentación técnica clara, mantenible y orientada a uso real.

## Entrada esperada

Módulo, API, script, repo, comando o flujo de trabajo.

## Instrucciones

No documentes lo que no puedas inferir. Si falta información, marca `Pendiente de confirmar`.

## Procedimiento

1. Identifica audiencia: usuario, desarrollador, mantenedor o investigador.
2. Resume propósito.
3. Explica instalación o requisitos.
4. Explica uso básico.
5. Añade ejemplos.
6. Añade troubleshooting si aplica.

## Salida

```markdown
# Título

## Propósito

## Requisitos

## Uso rápido

## Ejemplos

## Configuración

## Flujo interno

## Problemas frecuentes

## Pendiente de confirmar
```
