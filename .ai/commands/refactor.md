# /refactor

## Propósito

Planificar y ejecutar refactors seguros, incrementales y comprobables.

## Entrada esperada

Código, módulo o problema de mantenibilidad.

## Instrucciones

No cambies comportamiento salvo que se indique. Prioriza pasos pequeños y tests.

## Procedimiento

1. Identifica smells o deuda técnica.
2. Separa cambios mecánicos de cambios semánticos.
3. Propón una secuencia de commits o pasos.
4. Define pruebas antes y después.
5. Evita refactors masivos sin verificación.

## Salida

```markdown
## Objetivo del refactor

## Comportamiento que debe preservarse

## Problemas detectados

## Plan seguro

| Paso | Tipo | Cambio | Verificación |
|---|---|---|---|

## Tests recomendados

## Riesgos

## Resultado esperado
```
