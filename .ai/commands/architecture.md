# /architecture

## Propósito

Diseñar o evaluar arquitectura de software con trade-offs explícitos.

## Entrada esperada

Nueva funcionalidad, rediseño, integración, sistema multiagente, API, pipeline o infraestructura.

## Instrucciones

Usa pensamiento sistémico. Si hay MCP `deep-thinker`, usa `systems_thinking` y `counterfactual`.

## Procedimiento

1. Define requisitos funcionales y no funcionales.
2. Identifica componentes.
3. Describe flujos de datos/control.
4. Compara al menos 2 alternativas arquitectónicas.
5. Evalúa trade-offs.
6. Propón arquitectura recomendada.
7. Incluye plan de migración si aplica.
